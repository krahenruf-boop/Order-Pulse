# 客单价监控

入口：`/#aov-monitor`。自动监控默认关闭；店铺监控、飞书推送分别选择，不预置业务阈值。

设置直接列出当前授权目录的全部TikTok店铺，可搜索并勾选监控、飞书推送，无需逐一添加。点击店铺名称后，产品组和成员SKU从现有目录自动生成，可搜索、勾选并设置显示名称。显示名称仅用于页面与后续消息，不改变产品身份、SKU分组、统计范围或告警连续次数；留空使用原名称。未操作的未勾选店铺不会被保存为新增监控范围。

## 数据口径

- 店铺 × 现有产品组，只监控24小时、72小时，对比前一等长时段。统一冻结截止，读取最近6天订单（72小时本期＋72小时前期）。
- 平台订单号保留字符串；跨来源须确认店铺映射，SKU别名只按明确映射转换。
- 马帮字段优先，妙手补空值。金额、币种、整单口径作为整体；零不算空，错误值不被替换。
- 整单人民币金额 / 去重订单数。混合产品进入各相关产品组，不分摊。
- 已付款 ON_HOLD 计入；未付款、取消、全额退款排除；部分退款保留原整单金额并标注。
- 付款时间按来源实际时区转换，窗口左闭右开。Wise直接汇率仅作参考，失效超过24小时不展示外币，不影响人民币。

## 来源核验注意

妙手历史订单 `appRefundStatus=0` **不代表没有完成退款**。真实核验发现，售后已成功的全额及部分退款仍可能在历史订单标记为0。因此每轮正常UI读取两类售后列表（签收前、签收后），检查店铺、分页、首尾稳定性后再合并；不依赖该旧标记。

仅已核验完成状态参与退款金额判定。未识别状态、金额币种不一致、店铺授权异常、分页不完整均阻止受影响店铺的告警与恢复，保留上次完整结果。不会把来源请求失败当作“无订单”。

所有浏览器操作使用现有绑定与互斥锁；用户接管时停止，不自动接管。来源核验合同保存在本机 `aov_source_verification`，不包含凭据。新监控范围可先保存，标为待核验；手动完整检测通过后才进入自动检测。已有通过核验且配置未变的店铺产品范围继续运行。更改阈值、映射或范围会使对应范围重新待核验，修改显示名称不影响核验。

## 调度和通知

- 独立后台任务按北京时间偶数整点每2小时运行；唯一时间槽持久化。恢复后只补最新槽。
- 连续两次自动检测同方向越界，且两期都达最低订单数才通知。默认最低10单。
- 手动检测不计连续次数、不推送；持续异常不刷屏，恢复通知一次。
- 金额与百分比任一越界即可；触边正常。四个窗口合并为同店铺产品组一条消息。
- 已发送或发送结果不确定的事件不自动重发。配置变化重置连续状态。
- 不完整数据、采集失败只进入页面和检测记录，不发异常推送。

## 存储与接口

增量创建 `aov_monitor_*` 表，保留原数据库和历史。只存订单身份、付款时间、SKU、整单金额、退款状态及对账来源，不存买家资料。

接口位于 `/api/aov-monitor/`：`state`、`config`、`mappings`、`detect`、`history`及订单对账明细。页面关闭不取消后台检测，查看历史不重新采集。

## 验证

定向测试：`tests/test_aov_monitor.py`。外部来源、Wise、飞书均有隔离测试替身；真实验收另外记录，不能将替身结果视作真实发送成功。

已核验的试点：巴西52店、H标腰带扣黑色；用户确认妙手 `HBYDK2` 对应马帮 `HBYDK1*2`。上线不自动为其它店铺建立映射或阈值。

## 店铺卡片（2026-10）

- 工作台按店铺展示，两列/窄屏单列；默认五个实采产品组，按所选窗口去重订单数排序。店铺总单量直接由订单汇总，不能累加产品组单量。
- 两站目录使用真实内部 ID。仅共同平台 ID、唯一同名或唯一已核验标准化名自动匹配；身份冲突和多候选保持待匹配，手动选择只接受目录内真实授权店铺。
- 隐藏只影响展示。全部匹配店铺（包括隐藏店铺）共享6天查询，按需要自适应切片；退款按店铺核验。批次之间释放浏览器锁，已完成批次和冻结截止持久化，重启恢复队列。
- 实际订单的 SKU 按目录/已确认别名归组，未识别 SKU 独立显示。店铺默认阈值供新产品继承，旧产品规则保留为单独覆盖。隐藏和显示名不改变告警次数。
- 日期范围控件整体提交后再检查真实查询参数，避免分别编辑起止日期导致旧范围被恢复。没有成功验证请求参数的批次不会参与统计。
- 统计与通知分开；推送关闭时不生成告警状态。仅完整、已核验数据、当前周期的连续两次自动越界才能通知。过时周期只保留结果，不补发积压通知。
- `state` 提供 `shop_cards / directory / sync_progress`；配置接受局部 `changes`，避免全目录设置超出请求大小限制。失败批次可重试，保留成功批次；字段缺失必须再次核验，不能当作零订单。
- 旧快照保持原样，历史读取不采集、也不使用新汇率重算。

### 无妙手店铺与 SKU 隐藏

- 完整读取真实目录后，妙手确实没有的店铺标为“马帮统计”，无需手动匹配，参与同一批6天马帮查询。只有匹配店铺需要妙手订单和售后；妙手订单批次失败不会阻止马帮单来源店铺计算。
- 多候选、身份冲突、授权过期以及目录请求失败不视为不存在。无法确认的来源保留上次结果，不自动降级冒充完整双来源。
- 马帮单来源保留真实退款 UNKNOWN，不假设无退款。已确认付款、时间、金额和 SKU 的订单可展示参考统计；退款未核验时，该店异常及恢复通知暂停。页面、订单明细明确提示，后续可用退款字段核验后恢复资格。
- 单店设置自动列出实采 SKU，提供“隐藏 / 恢复”，保存后持久化。仅隐藏该店的展示标签；产品组成员全部隐藏时隐藏产品行，部分隐藏时仍展示原产品组完整统计。不改变单量、客单价、采集、规则或告警次数。历史快照不修改。
- 本期或前期少于10单时忽略异常，不产生异常或恢复通知；最低单量可设得更高，旧设置低于10时按10执行。

### 同步卡顿保护

- 浏览器绑定、连接和请求错误不按数据过多拆分；马帮无法读取时结束本轮并保留旧结果，避免重复生成大量失败批次。用户接管仍按原规则等待，不自动接管。
- 超过20家店的全量查询先按两天切片，必要时再细分。每片共享店铺查询，不逐店、逐SKU请求；同一冻结截止计算四个窗口。
- 采集超时先重载已验证且仍由Agent操作的马帮页面，取消旧页面的迟到操作，再允许较小查询。实际操作预算到期明确报告超时，不能让清理定时器先删除采集状态、误报普通传输错误。
- 重试只合并未读取的相邻时间片，按两天限制重新排队；成功批次及其时间范围、原始收据保持不变。旧错误任务和历史快照不删除。
